# Outputs

GalCraft writes output files under **`<outputDir>/<configuration-name>/`**. Here `<i>` is the **zero-based cube index** (`0`, `1`, ...); a single run may generate several separate spatial footprints.

## Complete output inventory

| File | When written | Contents |
| --- | --- | --- |
| `data_cube_<i>.fits` | Every completed cube | Synthetic spectrum per spatial pixel; optional simulated noise and wavelength axis. |
| `mass_fraction_array_<i>.npy` | Every generated cube | SSP age/metallicity/alpha population-weight grid across spatial bins. |
| `statistic_count<i>.npy` | During initial spatial binning | Count of input particles in each spatial bin. Note the absence of an underscore before `<i>`. |
| `particle_table_<i>.fits` | Only when `other_params.write_table: true` | Binned, filtered intermediate stellar-particle table; used for continuation. |
| `grids_distrib_<i>.png` | Each spectrum-generation run | Diagnostic maps summarising template-population quantities. |
| `datacube_distrib.png` | During initial binning | Catalogue particle distribution with cube footprints drawn over it. |
| `cube_list` | During initial binning | Comma-delimited list of cube centres. |
| `setup.json` | At end of run | Effective configuration after run-time preset and option changes. |
| `outputs.log` | Throughout run | Logs, progress details and warnings. |
| Additional statistics figures | When `other_params.plot_statistics: true` | Diagnostic plots generated by the spatial-binning path; names depend on the plotting calls. |

Continuation mode may reuse previously saved arrays/tables and skips already-present `data_cube_<i>.fits`; hence the output set can include files from an earlier run.

## FITS structure: `data_cube_<i>.fits`

| HDU | Extension name | Contents |
| --- | --- | --- |
| 0 | Primary | No science array; provenance and setup keywords. |
| 1 | `DATA` | Synthetic flux cube; Astropy loads as `(n_wavelength, n_y, n_x)`. |
| 2 when noise enabled | `ERROR` | Noise standard deviation, same shape and units as `DATA`. |
| Last | `WAVE` | One-dimensional output wavelength array in Å. |

`DATA` is recorded with `BUNIT = 10**(-20)*erg/s/cm**2/Angstrom`. The input in-memory array has axes `(x, y, wavelength)` and is transposed during FITS writing. The spatial WCS keywords specify longitude/latitude (either Galactic or equatorial, based on `x_coord` and `y_coord`) and the spectral header uses `AWAV`. Use `WAVE` as the authoritative spectral axis instead of inferring wavelengths from pixel indices.

### Optional noise model

With `add_noise: true`, the writer calculates a maximum-flux-based normalisation from `sn`, samples Gaussian noise in the flux cube, and stores its **standard deviation** in `ERROR`. This is a simplified simulation, **not** an empirically calibrated instrument noise/variance model. Zero/negative flux may invalidate assumptions of the square-root calculation.

### Read the FITS product

```python
from astropy.io import fits
import numpy as np

filename = 'output/test_kit/data_cube_0.fits'
with fits.open(filename) as h:
    flux = h['DATA'].data
    wavelength = h['WAVE'].data
    sigma = h['ERROR'].data if 'ERROR' in h else None

print('Cube shape:', flux.shape)
print('Number of wavelengths:', wavelength.size)
print('Median spectrum:', np.nanmedian(flux, axis=(1, 2)))
```

## NumPy population and count arrays

`mass_fraction_array_<i>.npy` stores the population-grid contribution in the dimension order **`(n_age, n_metal, n_alpha, n_y, n_x)`**. These are the code's accumulated SSP weights; verify their normalisation before interpreting them as a strictly mass-normalised probability distribution. Grid axis values depend on the SSP library selected.

`statistic_count<i>.npy` contains an `(n_y, n_x)` spatial particle-count grid in the orientation saved by the binner, which flips a transposed count array. Verify orientation before overlaying it on FITS WCS coordinates.

```python
import numpy as np

weights = np.load('output/test_kit/mass_fraction_array_0.npy')
counts = np.load('output/test_kit/statistic_count0.npy')

print('SSP weights:', weights.shape)
print('Particle counts:', counts.shape)
print('Summed SSP weights per spaxel:', weights.sum(axis=(0, 1, 2)).shape)
```

## Diagnostics and reproducibility

Always inspect `outputs.log`, `setup.json`, `datacube_distrib.png` and `grids_distrib_<i>.png` before analysing the cube. The retained JSON is the *effective* setup: for example, instrument spatial settings can overwrite user-provided values and observer settings can become `null` when the input was already transformed.

Use the [Configuration](configuration.md) and [Workflow](workflow.md) pages to connect these products with the flags and processing stages that generate them.
