# Input & Output

## Input files

### Stellar particle catalog

GalCraft was developed for **mock Milky Way catalogs generated from E-Galaxia**, but it can also be adapted to **cosmological or N-body / hydrodynamical simulations**. 

The input stellar particle catalog should contain the stellar population properties, positions, and velocities of individual particles, as summarised below.

| Category | Fields                                        | Description |
|---|-----------------------------------------------|---|
| **Stellar population** | `age`, `fe_h`, `m_ini`, `alpha_fe` (optional) | Stellar age, metallicity, mass, and optional α-element enhancement. |
| **Model-frame coordinates** | `px`, `py`, `pz`                              | Three-dimensional Cartesian positions of the stellar particles, with the Galactic centre at (0, 0, 0). |
| **Model-frame velocities** | `vx`, `vy`, `vz`                              | Three-dimensional velocity components of the stellar particles. |
| **Particle geometry** | `lgc`, `pzgc`, `rcgc`                         | Additional geometric properties describing each particle's position relative to the Galactic centre and disc plane, as detailed below. |
| **Extinction (optional)** | `exbv`                                        | Colour excess E(B−V) used to account for dust extinction. |

The particle geometry fields are defined as follows:

- **`lgc`**: Azimuthal angle of each particle around the Galactic centre, ranging from 0° to 360°.
- **`pzgc`**: Vertical distance of each particle from the Galactic disc plane. If the disc lies in the x–y plane, `pzgc = pz`.
- **`rcgc`**: Three-dimensional distance of each particle from the Galactic centre. For a Galactic centre at (0, 0, 0), `rcgc = sqrt(px² + py² + pz²)`.

The catalog should be saved into the chosen `modelDir` before running GalCraft


### SSP spectral templates

SSP spectral templates are used to assign a spectrum for each stellar particle based on its age, metallicity and, where available, α-element enhancement.
GalCraft currently supports four simple stellar population (SSP) spectral libraries:

- **MILES**
- **PEGASE-HR**
- **α-MC**
- **X-shooter (XSL)**

Please ensure that you download the required SSP templates and save them in your chosen `templateDir` before running GalCraft.

## Output files

Results are written to **`<outputDir>/NAME/`**, where `NAME` is the configuration name. 
For a run generating multiple pointings, `<i>` denotes the index of each pointing.

### Output file list

| File | Contents                                                                                        |
| --- | -------------------------------------------------------------------------------------------------|
| `data_cube_<i>.fits` | Synthetic data cube of each pointing.                                                           |
| `mass_fraction_array_<i>.npy` | SSP age/metallicity/alpha population mass weight grid across spatial bins.                      |
| `statistic_count<i>.npy` | Number of particles included in each spatial bin. |
| `particle_table_<i>.fits` | Stellar particle catalog used for each pointing.                    |
| `grids_distrib_<i>.png` | A plot summarising stellar population properties in each pointing.                                     |
| `datacube_distrib.png` | A plot showing the pointing footprints.                             |
| `cube_list` | A list of data cube pointing coordinates.                                                           |
| `setup.json` | Effective configuration after run-time preset and option changes.                               |
| `outputs.log` | Logs, progress details and warnings.                                                            |
| `particles_distrib.png` | Input-particle distribution plot generated by the binner.                                       |


### FITS structure: `data_cube_<i>.fits`

| HDU | Extension name | Contents                                                  |
| --- | --- |-----------------------------------------------------------|
| 0 | Primary | No science array; provenance and setup keywords.          |
| 1 | `DATA` | Flux cube; Astropy loads as `(n_wavelength, n_y, n_x)`.   |
| 2 when noise enabled | `ERROR` | Noise standard deviation, same shape and units as `DATA`. |
| Last | `WAVE` | One-dimensional output wavelength array in Å.             |

**Note**: 
- `DATA` is recorded with `BUNIT = 10**(-20)*erg/s/cm**2/Angstrom`. 
- The spatial WCS keywords specify longitude/latitude (either Galactic or equatorial, based on `x_coord` and `y_coord`) and the spectral header uses `AWAV`. 
- Use `WAVE` as the authoritative spectral axis if wavelengths inferred from the header are inconsistent.

### Read the FITS product

```python
from astropy.io import fits
import numpy as np

filename = 'output/test_kit/data_cube_0.fits'
with fits.open(filename) as h:
    flux = h['DATA'].data
    wavelength = h['WAVE'].data
    sigma = h['ERROR'].data if 'ERROR' in h else None

print('Cube shape:', flux.shape)
print('Number of wavelengths:', wavelength.size)
print('Median spectrum:', np.nanmedian(flux, axis=(1, 2)))
```


### NumPy population and count arrays

`mass_fraction_array_<i>.npy` stores the population-grid contribution in the dimension order **`(n_age, n_metal, n_alpha, n_y, n_x)`**. 
These are the code's accumulated SSP mass weights.
The grid axis values depend on the SSP library selected.

`statistic_count<i>.npy` contains an `(n_y, n_x)` spatial particle-count grid.

```python
import numpy as np

weights = np.load('output/test_kit/mass_fraction_array_0.npy')
counts = np.load('output/test_kit/statistic_count0.npy')

print('SSP weights:', weights.shape)
print('Particle counts:', counts.shape)
print('Summed SSP weights per spaxel:', weights.sum(axis=(0, 1, 2)).shape)
```

## Diagnostics and reproducibility

Always inspect `outputs.log`, `setup.json`, `datacube_distrib.png` and `grids_distrib_<i>.png` before analysing the cube. The retained JSON is the *effective* setup: for example, instrument spatial settings can overwrite user-provided values and observer settings can become `null` when the input was already transformed.

Use the [Configuration](configuration.md) and [Workflow](workflow.md) pages to connect these products with the flags and processing stages that generate them.
